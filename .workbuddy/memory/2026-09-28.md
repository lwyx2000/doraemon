## 路线 C 研究：换一个有「行业 PE/PB 历史」的 akshare 接口 —— 结论「不可行」

用户问「切到本地 base_sw_sector_daily」与「路线 C」含义。经查证：

### base_sw_sector_daily 数据来源（已查清）
- 本地 DuckDB 表（`database/schema.py` 建表），两条写入路径：
  1. **每日收盘快照** `get_sw_sectors`→`_save_sw_sector_snapshot`（sw_snapshot_job 每交易日 15:30 触发）：来自网关 `index_realtime_sw`(价)+`sw_index_first_info`(PE/PB当日)，**只落当日那一行有真实 PE/PB**。
  2. **历史回填** `backfill_sw_sector_history`：来自网关 `index_hist_sw`(价格日线)，**PE/PB 写死 NULL**（代码注释：免费源 sw_index_first_info 只有当日估值，无历史）。
- 结论：该表**眼下没有连续 PE/PB 历史序列**——只有当日快照有 PE/PB，历史行只有价格。所以「切到它」做不了行业估值分位/拥挤度（需 PE/PB 历史），只能做价格走势/相对强度（UI 已用）。

### 网关实测（外网 10.100.213.248:8000，2026-09-28 当日）
| 接口 | 用途 | 结果 |
|---|---|---|
| `index_analysis_daily_sw`(申万日线PE/PB) | 原行业历史源 | **500「Akshare 接口调用失败」**（2.2s 快返非超时） |
| `sw_index_daily_indicator`(按代码拉申万每日PE/PB历史) | 候选替代 | **500**（试了 symbol/index_code、data_type 大小写、有无日期 4 种组合全 500） |
| `stock_board_industry_hist_em`(东财行业日线) | 候选替代 | 200，但**仅价格/量 11 字段，无 PE/PB** |
| `stock_board_industry_spot_em`(东财行业实时) | 候选替代 | 200，但 10 项全价量，**无市盈率/市净率** |
| `sw_index_first_info`(申万行业当日PE/PB) | 当日源 | **200**，31 行业含 静态市盈率/TTM市盈率/市净率/股息率，**仅当日无历史** |
| `stock_board_industry_name_em`(东财行业清单) | 对照 | 200，496 板块 |

### 根因
网关 akshare 环境本身是活的（name_em/hist_em/spot_em/first_info 均正常）。但凡涉及「申万行业估值**历史**」的接口（index_analysis_daily_sw、sw_index_daily_indicator）全部 500 → 二者大概率共享同一底层上游（akshare 拉申万行业历史估值依赖的外部站点）在网关网络不可达 → **换 akshare 函数名救不了**，所有能返回行业PE/PB历史的接口都指向同一挂掉的上游。

### 最终结论（路线 C 不可行）
- **路线 C「换一个有 PE/PB 历史的 akshare 接口」不可行**：网关上不存在可用的行业 PE/PB 历史接口。
- 行业估值分位/拥挤度真正能点亮的只剩两条：
  - **路线 A**：等 `index_analysis_daily_sw`/`sw_index_daily_indicator` 上游恢复（代码已就绪，恢复即用）——最省事。
  - **路线 B 变体**：用当日源 `sw_index_first_info` 每日积累 PE/PB 到 base_sw_sector_daily（项目定时快照已在做，但需数月历史才有统计意义的分位样本）。
- 口径提醒：东财行业（stock_board_*）与申万一级（项目现用）是两套分类，即便走东财也面临口径切换成本，且东财 hist 无 PE/PB，仍需每日积累。
