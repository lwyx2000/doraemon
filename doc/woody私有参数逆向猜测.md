## 0. 一句话结论

palmmicro 的 `woody`（`arbcore/fetchers/woody_api_service.py` 的对上游）标 🔒 的
**校准值 / 对冲值 / 分时段锚点权重 / 期货期现 calibration**，大概率不是"知道真实持仓"，
而是**每天收盘后跑一次的定时脚本**用三类基础动作产生的：

1. **事后除法** —— 校准值 = 标的点位 × 汇率 ÷ 当日官方净值
2. **一元回归** —— position = 净值日收益对标的日收益的最小二乘斜率
3. **回归校验** —— ~~分时段/多工具篮子权重 = `Σw=1 且 w≥0` 的约束最小二乘~~
   **（已修正，见 §3.2.1）**：权重以**持仓/篮子配置**为主（`Σw` 不等于 1、含负腿），
   回归只做**残差校验与符号确认**，不是权重的生成器

真正"私有"的不是知识、也不是算法，而是这三件：
- **每天跑出来的时间序列存档 + 几十次手工覆盖记录**（页面只展示最新一次，历史 🔒 登录）
- **候选工具池配方**（哪些 ETF/期货/指数进回归、约束怎么写）
- **欧/日交易所的盘中分时**（`^USO-EU` / `^USO-JP` 背后的"当日盘中价"）

前两件完全可以自主复现——日频历史数据都在，参数能**回溯重算**，不用等。
第三件要分两层看：**日收盘**网关能拿（港美已通、欧日装 yfinance 即得），
**盘中快照**才是真缺口，而且它缺的不是"买不到"，是"**没人存过历史**"。

> ⚠️ 2026-11-03 用数据网关实测复核，本文原稿的三条"数据硬墙"判断**全部推翻了**：
> 外盘期货实时、商品现货基准价、港美 ETF 行情都能拿。详见 [§11](#11-网关实测复核2026-11-03)。
> 结论方向没变（"私有 = 先跑了 + 存档 + 登录壳"），但"要买数据/有硬墙"的说法作废。

## 1. 校准值：每天收盘后的一次除法

### 1.1 公式已经被 palmmicro 自己钉死

《估值说明文档》2.2.1 原话：**「校准值 = 标的点位 ÷ 单位净值」**，
并且"用上一交易日净值 + 当日标的涨跌"反推实时净值。

拿 2026-10-27 09:20 页面 15:00 收盘价数值验算，三只有代表性的：

| 代码 | 类型 | 标的 | 标的点位 | 单位净值 | 点位 ÷ 净值 | 页面校准值 |
|---|---|---|---|---|---|---|
| 159985 豆粕 ETF | 内盘商品 | M0 | 3199 | 2.1062 | **1518.85** | 1518.8491 ✓ |
| 518880 黄金 ETF | 内盘商品 | AU0 | 861.16 | 8.1769 | **105.32** | 105.3162 ✓ |
| 162411 华宝油气 | 海外行业 QDII | ^SPSIOP | 1375.70 | 1.0581 | **1300.14** | 1300.1359 ✓ |

三只全部对上，说明**"校准"这个动作就是一次除法**。QDII 类（如 161130 纳指）
校准值量级明显偏大（44903.6），是因为分子里额外乘了美元中间价——
`校准值 = 标的点位 × 汇率 ÷ 净值`。这一点文档 2.2.1 的算例里也明确列了汇率因子。

### 1.2 为什么这个"除法"看起来像魔法

因为它把一堆**"当日已知但会跳变"的信息**吸收进一个常数：
- 基金份额拆分/合并（净值断崖）
- 分红除权（净值不含息 vs 标的价格口径）
- 汇率基准切换（中间价 vs 即期）
- 标的选择带来的量级差异（NDX ~32000 vs NAV ~4.4，比值永远在同一量级附近漂）

第二天用 `标的现价 ÷ 校准值` 就等价于用 `最新官方净值` 重锚，
只是把锚藏在了分母里。

### 1.3 反推逻辑（本项目 undo.md §A.4 已给出）

单标的日频：

```
calibration_t = (nav_t + D_t × (1 − τ)) / (P_t × fx_t)
```

多工具篮子（lofarb 侧）：

```
calibration = Σ w_i × P_i_base × fx_i_base / nav
hedge_i     = calibration / position
```

分红/拆分事件（`D_t > 0`）必须走手工校准——文档 3.15⑥ 说得很直白：
**"XOP 分红除权，需要手工校准"**。手工校准 = **覆盖那一天除法算出的数**。
这条最能证明校准值就是除法：不然"覆盖"没意义，也不会有"每年 20 次"的琐事抱怨。

### 1.4 本项目其实不需要它

本项目走的是**"每日重锚 + 涨跌幅推净值"**（矩阵公式），
和"每天独立除法算校准值"是同一件事的两种写法：

```
nav_t × (P_now / P_base) × (fx_now / fx_base)
  ≡
(P_now × fx_now) / calibration        其中 calibration = P_base × fx_base / nav_t
```

单币种时两边精确等价。undo.md §T.2.2 就是这个判断。**结论：项目要不要校准值不重要，
重要的是它背后的标的选择、篮子权重和汇率口径**——那三样才是真正难复制的东西。

## 2. position：日频回归出来的斜率 β

### 2.1 猜测的做法

Woody 手上每天有：
- `nav_ret_t`（官方净值日收益率，滞后 1~2 日公布）
- `index_ret_t`（所选标的的日收益率，他自选自算）

对过去 N 天做一元 OLS：

```
nav_ret_t = β · index_ret_t + α + ε_t
```

`β` 就是页面上的"仓位系数"。这不需要任何人告知真实持仓。

### 2.2 这条猜测能解释文档里的观察

3.15② 的原话："ETF 通常都是 100% 仓位，LOF 一般不超过 95%，**QDII 额度紧张时降到
90%，华宝油气历史上曾降到 80%**。"

如果 position 是从年报读的，那它按季跳变；如果 position 是回归 β，那它会随
市场结构、汇率、基金规模变化**连续漂移**——文档描述"90% / 80% 曾经到过"的
语气明显是后者。

### 2.3 本项目已经在做完全一样的事

`qdii_baskets.json` 里 159985 的注释：

> "position 88.9 是**实测净值弹性 beta**（名义近满仓，差额来自保证金/现金与 M0 主连的期限差），不是名义仓位。"

日经系 501303=99.0、161127=96.3、513880=97.0 也全部标的是**实测净值弹性 β**，
和 palmmicro 的名义仓位 1.00 有意不同。

也就是说：项目独立做出来的 position 语义，**理论上应该收敛到 Woody 的 position**。
两边数字对不上时的差异（比如原油三兄弟 82.32 vs 0.86），大概率来自：
- 回归窗口选取不同（60d / 90d / 250d）
- 锚点折叠（本项目把 `^USO-EU` 折进 USO 单锚，多锚点稀释了 β）
- FOF 结构（净值弹性天然低于名义持仓）

**要缩小差异，正确姿势是拿净值序列跑一遍回归复核**——不是照抄 palmmicro 的 0.86。

## 3. 分时段锚点权重：持仓配置 + 回归校验（原稿误标为"约束最小二乘"，见 §3.2.1）

### 3.1 长什么样的权重

《估值说明文档》附录 B/C 和 undo.md §D 里的这些是典型形态：

- `501018 南方原油`：`^USO-EU 64.93 + USO 35.07 + ^INDA-US 14.71`
- `161129 易方达原油`：`^USO-EU 49 + ^USO-JP 14.71 + ^USO-HK 2.94 + USO 49`
- `160216 国泰商品`：`IAU +1、GLD +1、UGL +2、ZSL −2、DJP −1、SCO −2`
- `162411 华宝油气`：`DRIP −2 + GUSH +2`（镜像差分）

一眼看上去像"内幕"，但它的**存在理由**都能用"残差最小化"解释——注意是"解释为什么有这条腿"，
不是"这条腿的系数是约束回归跑出来的"（后者是原稿的错误，见 §3.2.1）。

### 3.2 猜测的做法（约束式已修正，见 3.2.1）

候选工具池由人工挑（这是唯一需要"经验"的地方），比如对原油 LOF 扔进：
`USO 美股收盘、^USO-EU 伦交收盘、^USO-JP 日交收盘、^USO-HK 港交收盘、CL 期货夜盘`。

拿一个观测窗（60~90 天），跑**带符号**线性回归：

```
nav_ret_t = Σ w_i · tool_i_ret_t + ε_t        （无 Σw=1 / w≥0 约束，允许负权重）
```

为什么 `^USO-EU` 常常拿到最大头（64.93/49）？因为欧洲时段先反映原油市场情绪，
A 股盘中信息主要来自欧盘——回归会自然把权重推向"信息含量高的那个源"。

### 3.2.1 原稿的 `Σw=1, w≥0` 约束是错的（自相矛盾）

原稿写"带约束 QP：`Σw=1, w≥0`"，但**它自己举的例子直接违反这两个约束**：

| 例子 | 权重和 | 含负权重 | 与 `Σw=1, w≥0` |
|---|---|---|---|
| `162411 DRIP −2 + GUSH +2` | **0** | ✅ −2 | ❌ 两条都违反 |
| `160216 IAU+1 GLD+1 UGL+2 ZSL−2 SCO−2 DJP−1` | **−1** | ✅ −2/−1 | ❌ 两条都违反 |
| `501018 ^USO-EU 64.93 + USO 35.07 + ^INDA-US 14.71` | **114.71** | ❌ | ❌ 和不等于 1 |

**正确的读法**：这些数字是**带符号的敞口系数（多空腿配平）**，不是"仓位份额"。
`Σ|w|` 远大于 1 是正常的——同一份净值敞口被拆成多条腿去抵消噪声（§3.3），
和"资产配置权重和为 1"是两套语义。原稿把两者混在一起了。

另外还有一层过度推理：**60~90 天窗口、4~6 个高度共线的原油代理，权重根本不可识别**
（USO / ^USO-EU / ^USO-JP 的日收益相关性常在 0.95 以上），OLS 解会随窗口微调
剧烈跳动，**不可能稳定跑出 `64.93 / 49 / 14.71` 这种两位小数**。这种"两年不变、
精确到分"的形态更像**持仓/配置口径**（本项目 `qdii_baskets.json` 的 `_comment`
就明写权重"移植自 lofarb 配置（2026-10 持仓口径）"），而不是每天回归的输出。

**修正后的猜测**：权重以**持仓/篮子配置**为主（人工或披露得来），回归只用来
**校验残差、定符号、择锚点**。这仍然不需要"内幕"，只是不是"约束最小二乘自动生成"。

### 3.3 反向工具对：DRIP(−2) + GUSH(+2) 是怎么跑出来的

文档 3.12 关键发现一的原话："**把发行商的跟踪误差和溢价对冲掉**"。用回归的语言讲：

- 单腿 XOP 回归：残差里含大量"溢价噪声 + 跟踪误差" → R² 只有 0.87
- 换成 `−DRIP + GUSH`（同一发行商、同一指数、方向相反、同为 2 倍杠杆）：
  两腿的溢价噪声**符号相反、可以互相消掉**，剩下的就是 XOP 真涨跌
- 残差平方和立刻下降，回归自然选这个组合

**这一对腿的存在**是"残差最小化挑工具"的结果（噪声互消可以直接验证）；
但系数 `±2` 这个**具体倍数**更像人为配平或杠杆归一，不是 OLS 给出的最优值。

### 3.4 160216 的五腿结构同理

`IAU(+1) + GLD(+1) + UGL(+2) + ZSL(−2) + SCO(−2)` 就是：
- 黄金腿：IAU + GLD 两只现货金 ETF（+2 汇总）
- 白银腿：UGL 做多（+2）
- 农产品腿：ZSL 做空（−2，抵消白银波动）
- 能源腿：SCO 做空（−2，抵消原油波动）

这是回归跑出来的**净方向**——真实持仓肯定更粗，但"净值涨跌对哪个工具敏感多少"
是数据告诉他的。所以文档 3.13 讲"160216 是反向神器"，其实也是从回归系数的
符号反推出来的解读。

### 3.5 undo.md §D.4 那句话偏保守（但"数据卡点"要重新定位）

undo.md 说"权重从哪来仍是 A 类问题"。按 §3.2.1 修正后的读法，权重**主要来自持仓配置、
回归做校验**，私有性卡的是**欧/日盘中行情**，不是算法或知识。

但"卡点"的性质要说准，原稿这里说错了（原话是"欧/日/港交易所的收盘/分时数据公开接口都没有"）：

| 需要什么 | 用途 | 网关能不能拿 |
|---|---|---|
| 港/美 ETF **日收盘** | 权重校验、β 回归 | ✅ `tickflow_hk/us`、`easy_tdx_hk/us`、`akshare_hk/us` 三条容灾链 |
| 欧/日 ETF **日收盘** | 同上 | ⚠️ 装 yfinance 即得（`/api/yf/kline`），当前是**缺依赖**不是缺数据 |
| 欧/日 ETF **盘中价** | 盘中 EST 实时推送 | ❌ 真缺口（见 §11） |

**关键区分**：拟合日频参数只要**日收盘**，完全够；只有"A 股盘中要实时 EST"才需要
欧/日**盘中**价。原稿把这两件事混成"分时行情"，导致把门槛估高了。

**这一点对项目很有意义**：真要拿这套东西不需要求 Woody，需要的是把 yfinance 装上
（或自建欧日收盘抓取）。undo.md 附录 2 已经写了路径："雅虎日本/欧洲自建脚本可行"。

## 4. hedge：只是 calibration / position 的除法副产物

`hedge = calibration / position`（§A.4）。看起来是"魔法公式"的：

```
est_nav = base_nav × (1 − pos) + P_now × fx_now / hedge
```

把它展开——把 `hedge = P_base × fx_base / (nav × pos)` 代进去——
和本项目矩阵公式在"单成分 + 权重 100%"时**精确代数等价**：

```
nav × (1 + pos × (P_now/P_base − 1)) × (fx_now/fx_base)
```

所以 hedge **不是新信息**。它只是把 `P_base` 藏进一个"每天更新一次的常数"的写法。

之所以看起来神，是因为它把跨时区基准日选择变成了"读昨天的数"——但那个常数
每天仍然是通过一次除法算出来的。§A.6 提到的"161125 hedge 差 10 倍 / 161130 差 41 倍"
事故就是这个：hedge 常数一旦标的选择口径变了（NDX 指数 vs QQQ 价格量级差 20 倍），
常数立刻错位。反过来说明 hedge **不是**任何独立的秘密知识。

## 5. 期货期现 calibration：一次除法 + 一个现货基准源

§B 的 calib 模式：

```
calibration_t   = futures_settle_t / spot_t
equiv_spot_t    = futures_price_t / calibration_t
```

只要同时能拿到 AU0/M0 结算价 + 上海金交所 Au9999 或生意社商品指数现货价，
就是一次除法。

> **2026-11-03 实测更正**：原稿说"付费源 ~1k/年，卡的就是现货基准价"——**错的**。
> 网关 `futures_spot_price_daily` 直接能出：
> ```
> GET /api/ak?method=futures_spot_price_daily&start_day=2026-10-30&end_day=2026-11-03
> → {"date":"20261030","symbol":"C","spot_price":2174.29,
>    "near_contract":"c2611","near_contract_price":2184.0,
>    "dominant_contract":"c2701","dominant_contract_price":2221.0,
>    "near_basis":9.71,"dom_basis":46.71,
>    "near_basis_rate":0.00447,"dom_basis_rate":0.02148}
> ```
> 现货价、近月/主力合约价、基差、基差率**一次全给**。§5 的"~1k/年"结论作废，
> 期现 calibration **零成本可做**。

- **不是算法难**：除法谁都会
- **也不是数据源难**：现货价网关已在代理（东财/生意社口径）
- **真正的工作量**在"换月合约映射 + 基差口径对齐"：`near_contract`/`dominant_contract`
  会跳月，要和自己用的连续合约口径对齐，否则换月日算出的 calibration 有跳空

对本项目来说，`_estimate_by_futures` 已经用 pure 模式（直接拿结算价）跑通、
残差压到 0.061%~0.233%，**在日频估值上 pure 完全够用**。calib 模式的价值主要在
**换月跳空修正**（§B.5）——那是"要不要在换月日前后继续出数"的鲁棒性问题，
不是"估得更准"的问题。项目当前用"换月前后 3 日拒估"作为兜底，符合 §T.2.4
说的"宁可 '-' 也不造数"铁律。**现在有了 `futures_spot_price_daily`，这条路可以从
"拒估"升级为"补估"**（用基差率反推等效现货，跨换月连续），是本次复核里
对项目最有直接价值的一条。

## 6. 那"私有"到底是什么，一张表说清

| 内容 | 是否算法 | 是否数据 | 项目要复用有多难 |
|---|---|---|---|
| 校准值 / hedge 单日值 | ❌ 除法 | ❌ 只用公开数据 | **零成本可复算** |
| 校准值 / hedge 历史序列 | ❌ | ❌ 都能回溯（历史净值+历史点位） | 一次 backfill 补完，不用等 |
| position β | ⚠️ 需要回归 | ❌ 净值 + 指数都在公开源 | akshare 净值 + 指数日线，一晚上跑完 |
| 分时段锚点权重 | ⚠️ 配置为主，回归校验 | ✅ 港美日收盘已通；欧/日日收盘装 yfinance 即得 | 日频可做；**盘中**才卡 |
| 期货期现 calibration | ❌ 除法 | ✅ **网关已有现货价+基差** | 零门槛（§5 实测） |
| 候选工具池配方 | ⚠️ 经验 | ❌ | 靠反复回归 + 残差观察迭代 |
| 换月升贴水修正 | ⚠️ 需要历史 calibration 序列 | ✅ 历史现货价可回溯 | 一次性补历史即可，不用日积月累 |
| **盘中实时 EST 的欧日锚点** | ❌ 公式简单 | **❌ 历史盘中快照无人存档** | **只能从今天开始攒** |

真正"卡死整个体系上限"的确实只有 **1 项**，但原稿的理由（"买不到数据"）要换成
**"回溯不出历史"**：欧/日**盘中**分时。日频收盘网关能拿，历史能重建；
盘中价过去没人存，只能从今天开始录——所以缺的是**时间**，不是**钱**。

其他都可以在项目现有代码骨架上，**用公开数据 + 一次回归/一次 backfill** 复现出来。

## 7. 反向验证：这套猜测能不能解释 palmmicro 文档里的现象

逐条打分（不粉饰）：**✓ 强成立** / **◎ 方向对但机制要换** / **△ 偏弱，反过来还是反证**

| palmmicro 现象 | 猜测解释 | 判定 |
|---|---|---|
| **中美轮流休市校准错 1%**（3.15④ 2016 事故） | 分子分母来自不同交易日 → 系数错一个日波幅。1% 正好是"错一天"的量级。修复方案"只校当天、不满足就沿用最近一次"就是**跳过一次除法** | ✓ **最硬的一条**。只有"每日独立除法"才会这么怕日期错位；如果是净值重锚，中间那天的缺口会被自动吸收，不会出 1% 误差 |
| **161130 涨停时 NAV 严重滞后、EST 失灵**（3.13） | 那天没有可用官方净值做除法 → 公式退化到 10-26 的旧常数 | ✓ |
| **实时 EST = 参考 EST + NQ/ES 期货影响**（3.15①、2.4） | 在参考 EST 上叠加期货的晚间增量，套同一个 P→NAV 换算常数 | ✓ 但**只对量级相近的工具才成立**：NQ↔NDX 近似 1:1，所以复用同一常数看不出误差；`CL↔USO`、`GC↔IAU` 量级差几十倍，必须带比例项，不能直接套 |
| **分红除权要手工校准**（3.15⑥，D_t>0） | 两侧除息口径不对称（价格指数不计息 vs 净值扣分配、10~30% 预扣税漏损、分配到账时点差）→ 除法当天跳一个常数 | ◎ 机制要换。**不是"净值还没反映"**——多数情况是净值先反映、价格序列不反映（价格指数），或者两边反映幅度不同。处置也不是"覆盖一天"而是"把 `D×(1−τ)` 加回净值"（§1.3 公式），本质是一年 20 次的手工事件补偿 |
| **513800 停在 2025-09-29**（3.6） | 那天之后"当日净值 + 当日点位"再没同时齐过 → 除法一直没跑，值冻结 | ◎ 方向成立，但**断的是点位端，不是净值端**——已实测：`fund_etf_fund_info_em&fund=513800` 返回 1793 条，**2025-09-29 之后仍有 260 条净值，最新 2026-11-02 单位净值 1.8165**。基金活得好好的、净值天天在出。所以冻结只能是**标的价格端取不到**（`^USO-EU` 这类海外私有 symbol 映射失效/源挂了）。这反而**强化**了"私有锚点代码很脆弱"的判断：513xxx 是上交所跨境 ETF 号段，锚点在境外，一家数据源一改代码就整只冻结 |
| **仓位系数随 QDII 额度掉到 0.90/0.80** | 原稿写"β 回归窗口换季自然漂" | △ **原解释反了**。额度紧张是**实际持仓真的降了**，回归只是**观测**它，不是"窗口滚动导致漂移"。而且 60~90 天 OLS 不会正好落在 0.90/0.80 这种整档上（只会给 0.917 / 0.883）。要么 Woody 做了取整/收缩，要么 position 是"披露名义仓位 + β 校验"的混合口径。**这条其实是纯回归说的轻度反证** |
| **校准时间落在 16:00~23:12、每天一次**（3.15⑤ 20 行） | 原稿写"收盘后跑一次的定时任务" | △ 更像**净值到达时间**而非 cron 时刻：QDII 净值 T+1/T+2 才出，16:00 到的多是港/日系、23:12 到的多是欧美系。"**等数据齐了才跑**"的事件驱动比固定 cron 更符合这个分布——而这正好和上一条"冻结"同源：等不到就一直不跑 |

**修正后的结论**：7 条里 **3 条强成立**（④事故、161130、实时 EST）、**2 条方向对但机制要改**
（分红、513800）、**2 条偏弱甚至反向**（position 整档、校准时刻）。整体仍然自洽——
"每日除法 + 回归校验 + 手工事件补偿 + 等数据齐了才跑"这套骨架能解释全部现象；
但**不能**说"没有一条解释不了"，也不能靠这几条反推"权重是约束 QP 自动跑出来的"。

## 8. 对项目意味着什么

如果这套猜测成立，可以推三条：

1. **不需要求 Woody 的私有数据**，也不再需要买数据。网关实测（§11）已确认：
   外盘期货实时、商品现货+基差、港美 ETF 行情**全都能拿**；欧/日只是 yfinance 没装。
   日频参数（校准值 / position / 权重 / 换月修正）**全部可以回溯重建**，
   不用像 Woody 那样"从今天开始每天攒"。唯一回溯不出的是**欧/日盘中快照**——
   它只影响"盘中实时 EST"的精度，不影响日频估值（项目当前也用不到盘中）。

2. **position 应该用回归复核，不该照抄 palmmicro**。原油三兄弟 4~10 个百分点
   的差异（82.32 vs 86.0）是**"实测 β" vs "名义仓位"**的语义差，不是 bug。
   T3 那套 `est_nav_history` 每日回填机制刚好可以做这个验证——
   如果哪个 position 用错了，误差列会持续偏，一眼可见。

3. **锚点折叠可以进一步做**。项目已把 lofarb 的原篮子折叠到 akshare 可得锚点
   （§D.5 已落地：^INDA-US → 159985 中锚 USO → 美股锚）。**下一步**：用现有
   `est_nav_history` 的误差数据反向找哪些基金"折叠得太狠、残差还在 0.30 附近"，
   给它们补一条**内盘对应 ETF 分时**（比如原油 LOF 补一条 159930 能源期货 ETF
   做"盘中同步锚"）——这是完全在 akshare 能力范围内的改造。

## 10. 一句话回到最初的问题

> **Woody 是不是真的"知道"基金持仓？** 大概率不是。
> **那他手上的私有数从哪来？** 一套每天跑一次的定时脚本 + 约束回归 + 少量手工
> 覆盖（分红、除权、假期对齐）。用的都是公开或半公开数据，只是他先跑了、
> 存了他自己的服务器、加了登录壳。
> **项目要不要跟着做？** 项目已经在做，只是**用官方净值日更重锚**替代了**日更
> 校准值**——数学等价、更稳。真正值得补的是**分时段锚点的行情源**（§D.5）
> 和**溢价率历史统计口径**（§K），这两块是纯数据接入，不是算法改造。

**2026-11-03 复核后补一句**：上面三段结论都成立，但"**约束回归**"要改成
"**持仓配置为主 + 回归校验**"（§3.2.1），"**私有**"的落点要从"数据源"
移到"**时间 + 运维**"（§11.3）——Woody 真正的壁垒不是"他有你没有的数据"，
而是"他三年前就在每天存，你没有那三年"。

## 11. 网关实测复核（2026-11-03）

复核对象：AkShare WebAPI 网关 `http://10.100.213.248:8000`
（能力目录 `http://10.100.213.248:8085/catalog` → 内部走 `/api/project/catalog`、
`/api/project/info`、`/openapi.json`）。
网关代理 **1186 个 AkShare 方法**，另有 `/api/quote/*`、`/api/yf/*`、`/api/futu/*` 原生路由。

### 11.1 原稿"拿不到"的东西，逐条实测

| 原稿判断 | 实测 | 结果 | 判定 |
|---|---|---|---|
| 外盘期货实时 = "唯一硬墙"（§8.1 旧文） | `GET /api/ak?method=futures_foreign_commodity_realtime&symbol=CL` | `{"名称":"NYMEX原油","最新价":97.871,"涨跌幅":1.4628,"日期":"2026-11-03","行情时间":"16:04:07"}` | ❌ **能拿**，实时到分钟 |
| 商品现货价 / 期现 calib 要付 ~1k/年（§5 旧文） | `GET /api/ak?method=futures_spot_price_daily&start_day=…&end_day=…` | `spot_price / near_contract_price / dominant_contract_price / near_basis / dom_basis / near_basis_rate / dom_basis_rate` | ❌ **能拿**，直接给基差率 |
| 外盘合约池不可知 | `futures_foreign_commodity_subscribe_exchange_symbol` | CL / GC / SI / OIL / XAU / XAG / NG / HG … | ❌ **能拿** |
| 港股 ETF 行情（§0 旧文算作缺） | 目录 `datasources.details` 容灾链 | `tickflow_hk / easy_tdx_hk / akshare_hk` 三级 | ❌ **能拿** |
| 美股 ETF 行情 | 同上 | `tickflow_us / easy_tdx_us / akshare_us` 三级 | ❌ **能拿** |
| 欧/日挂牌 ETF 分时 | `GET /api/yf/realtime?symbol=^N225` | HTTP 200 但 `{"source":"none", …全 null}` —— **yfinance 未安装** | ⚠️ 能力有、**依赖缺** |
| 全球指数 | `index_global_spot_em` / `index_global_hist_em&symbol=日经225` | 20s / 30s 均无响应（HTTP=000） | ⚠️ 东财源慢或被限，需降级 |

### 11.2 由此产生的三条修正

**① "私有清单"从 3 项降到 1 项，而且性质变了。**
原稿 §0 列 3 项私有物，第 3 项"欧/日/港分时行情"现在只剩"欧/日**盘中**"。
更关键的是性质变了：**不是买不到，是回溯不出**。日收盘能拿（装 yfinance 即得），
历史收盘价也能回溯重建；但"2024-06-13 伦敦时间 11:30 的 ^USO-EU 报价"这种盘中快照，
当初没人存，现在任何源都补不回来。**缺的是时间维度，不是钱。**

**② 日频参数与盘中 EST 是两个不同的门槛，原稿把它们混成了一个。**

| 用途 | 只需要 | 门槛 |
|---|---|---|
| 校准值 / position β / 权重校验 / 换月修正（全是**日频**） | 标的**日收盘** + 官方**日净值** | 低：网关 + akshare 净值，一次性 backfill 能重建**过去几年**全序列 |
| 盘中实时 EST（A 股 09:30–15:00 要有欧日锚点在动） | 欧/日**当日盘中价** | 高：只能从今天起录，或用期货/ADR 代理 |

原稿 §3.5 说"权重拟合需要每个候选工具的分时价格序列"——**错的**，日收盘就够拟合。

**③ §5 的付费结论作废，且给项目带来一个正向机会。**
`futures_spot_price_daily` 直接给 `dom_basis_rate`，意味着 `_estimate_by_futures` 的
换月期可以从"换月前后 3 日拒估"升级成"**用基差率反推等效现货、跨换月连续出数**"。
这是本次复核里对项目**最有直接价值**的一条（§5 末段已补）。

### 11.3 对"Woody 私有性"总判断的微调

原稿说"私有 = 先跑了 + 存档 + 登录壳"。**判断成立，但三件私有物的权重应当重排**：

| 私有物 | 原稿权重 | 复核后权重 | 理由 |
|---|---|---|---|
| 算法/公式 | 低 | **低（确认）** | 除法 + OLS，无门槛 |
| 数据源 | **高**（"硬墙""要买"） | **低** | 网关已覆盖，欧日只缺依赖 |
| 历史序列存档 | 中 | **中高** | 不是"别人算不出来"，而是"别人没从三年前开始存" |
| 手工覆盖记录（分红/停牌/份额变动） | 低（"每年 20 次琐事"） | **中** | 真正靠时间磨出来的东西，且**不可批量回溯**：知道某天该覆盖，要靠当时的人工判断记录 |

一句话收口：**Woody 的壁垒是"时间 + 运维"，不是"数据 + 算法"。**
任何人一周内确实能重跑出一套**日频等价参数**（历史数据可回溯），
但跑不出"**同一套参数下连续三年的样本外记录**"——那需要真的等三年。
这才是 🔒 的真正含义。

### 11.4 一个可证伪点的实测（513800 冻结，§7 第 5 行）

§7 里 513800 那条原以为"两个方向都可能"，实测一下就有答案：

```
GET /api/ak?method=fund_etf_fund_info_em&fund=513800
→ 1793 条；2025-09-29 之后仍有 260 条；最新 2026-11-02 单位净值 1.8165
```

**净值端完全正常**。所以冻结不在净值侧，只能在**标的价格侧**：Woody 给这只跨境 ETF
配的境外锚点（`^xxx` 那类私有代码）从 2025-09-30 起取不到价了。

这条实测的价值：它把"等数据齐了才跑"从一个**中性解释**变成了**指向性证据**——
冻结位置精确落在"他自己维护的境外 symbol"上，而不是落在公开的净值接口上。
**私有锚点代码是这套体系最脆的一环**，也解释了为什么这类页面会出现"个别基金静默卡死
半年以上而没人发现"：脚本不报错、只是不更新。
