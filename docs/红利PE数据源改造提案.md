> 背景：红利基金页 `/dividend-funds`「红利指数估值与仓位信号」的 `pe` / `pe_percentile` / `pe_min`/`pe_max` 经常整列为空。

## 一、问题定性（已查实，非猜测）

### 1.1 当前可用度

| 状态 | 数量 | 说明 |
|---|---|---|
| PE 正常 | **31 / 44** | 分位、分位区间、`pe_series` 均正常，窗口最高 2613 天 |
| PE 结构性缺失 | **12** | 中证接口不提供该指数，解封也不会恢复 |
| PE 并发瞬时失败 | **1**（`930838`） | 单独调正常，6 并发批量构建时失败 |

### 1.2 三个独立根因

**根因 A：中证源不覆盖（12 个，结构性）**

akshare `stock_zh_index_hist_csindex` 直接打中证官网，以下代码中证没有：

| 类型 | 指数 |
|---|---|
| 深市代码 | `399324` 深证红利 |
| 华证系 | `995082` / `995128` / `995127` |
| 港股·标普·富时 | `SPAHLVCP` `HSSCHKY` `SPCADMCP` `spdjicspsadrp` `HSMCHYI` `hkH11153` `GPCCH003.FI` `XH150CH` |

典型报错（非限流）：
```
ValueError: Length mismatch: Expected axis has 0 elements, new values have 16 elements
```
即中证返回**空 DataFrame**，akshare 赋列名时炸。

**根因 B：中证官网限流（长期反复）**

失败历史（akshare-backend 日志）：

| 日期 | 失败次数 |
|---|---|
| 10-06 | 1347 + 972 |
| 10-07 | 599 + 377 |
| 10-08 09点 | 377 |
| 10-08 11点 | 59 |

限流时表现为 `JSONDecodeError`（中证返回非 JSON 响应）。

**根因 C：并发瞬时失败（隐蔽，最坑）**

`_fetch_index_hist('930838')` 单独跑 2613 行正常；6 并发批量构建时**返回行存在但 PE 列全空**。

⚠️ **这种失败不抛异常** —— 所以日志里搜不到「指数指标构建失败」，只表现为"该指数字段空"。排查此类问题必须单独调函数对比，不能只看 overview 输出。

### 1.3 加重问题：6h 缓存把空结果冻住

`dividend_service.py:1007`：
```python
if force or not _INDEX_CACHE["data"] or (now - _INDEX_CACHE["ts"] > INDEX_CACHE_TTL):
    ...
    indices = [x for x in indices if x]
    _dy_save_to_db(indices)
    if indices:                      # ← 只有非空才更新缓存
        _INDEX_CACHE["data"] = indices
```

一旦整批失败（`indices` 为空列表），旧的空结果会被继续沿用 **6 小时**，页面持续空白。**限流解除后不会自动恢复，必须点刷新。**

## 二、方案 1：PE 序列本地累积（推荐）

### 2.1 可行性验证结论 ✅

已实测确认：

| 验证项 | 结果 |
|---|---|
| 分位/分位数是否依赖全量序列 | **是**。`pe_percentile` / `pe_min` / `pe_max` / `pe_p25` / `pe_median` / `pe_p75` / `window_days` 全部由 `pe_values`（全历史排序后算出） |
| 需要的序列长度 | **全量**（`HIST_START="20160101"`，`window_days` 实测 2613 天）——不能只存最新值 |
| 单指数行数 | 2613 行 |
| 44 指数合计 | 约 **115,000 行** |
| 估算体积 | **约 4.4 MB**（含索引开销） |

体积对 DuckDB 而言完全无压力。

### 2.2 现状：股息率已本地化，PE 序列没有

`dividend_service.py:240` 已有现成范式：
```python
DY_DDL = """
CREATE TABLE IF NOT EXISTS base_dividend_index_dy (
    code VARCHAR PRIMARY KEY, name VARCHAR,
    dy DOUBLE, dy_date VARCHAR, updated_at TIMESTAMP
)
"""
```
股息率落库 + `_dy_last` 兜底 + `dy_stale` 标记都已实现，**PE 序列照抄这个模式即可**，无需新设计。

### 2.3 改动方案（4 处，全在 `dividend_service.py`）

| # | 改动 | 说明 |
|---|---|---|
| 1 | 新增 `PE_DDL` 表 `base_dividend_index_pe` | `(code, date, pe)` 复合主键 + `(code, date)` 索引 |
| 2 | 新增 `_save_pe_series(code, rows)` | 增量 upsert，只写新日期，已有日期跳过 |
| 3 | 改造 `_build_index_metric` 取数段 | **优先读本地库**；仅当本地为空或最新日期落后于今日时才打上游，成功后回写。取数失败时用本地最后值+ `pe_stale` 标记（对齐 `dy_stale` 做法） |
| 4 | 返回体加 `pe_stale` 字段 | 前端可提示"数据陈旧"，避免静默失败再次让页面空白 6h |

**关键：第3 条采用「本地优先 + 上游补最新」的策略**，不是完全切断上游。这样：
- 日常运行 = 1 次轻量请求/指数（只取当日增量），限流影响面极小
- 上游全挂时 = 仍有本地全量历史，分位/区间照常显示
- 首次回填 = 一次性拉全量（44 × 2613 行），之后只补增量

### 2.4 预期收益

| 收益 | 说明 |
|---|---|
| 根治限流影响 | 分位/区间不再依赖实时抓取 |
| 根治并发失败 | 单一失败只影响当日增量，历史分位不受影响 |
| 修复 6h 空结果冻结 | 本地兜底后 `indices` 恒非空，缓存不再冻空 |
| 响应变快 | 消除每次 overview 的 44 次上游调用 |
| 与股息率逻辑一致 | 复用已验证的 `_dy_save_to_db` 范式 |

### 2.5 风险与成本

- **需回填历史数据**：首次上线要一次性抓 44 × 2613 行，中证当前有限流风险，建议**分批低并发（≤3）+ 断点续传**回填，避免再触发封禁
- 改动 `dividend_service.py` 属核心逻辑，需你拍板
- 首次上线后建议观察一次 overview 耗时对比

## 三、方案 2：12 个结构性缺失另接数据源（不推荐现在做）

### 3.1 数据源难度评估

| 指数类型 | 可行来源 | 难度 |
|---|---|---|
| `399324` 深证红利 | 深交所官网 / 国证指数 `cnindex.com.cn` | 中等 |
| 华证系 `995xxx` | 华证指数官网 `hsi.com.hk` | 中等 |
| 港股恒生系 | 恒生指数公司 `hsi.com.hk` | 较高（恒生有 API 限制） |
| 标普系 `SP*` | 标普道琼斯指数官网 | 高 |
| 富时 `GPCCH003.FI` / `XH150CH` | 富时罗素官网 | 高（多语言站点 + 反爬） |

### 3.2 建议

**先不做。** 理由：
1. 31/44 已覆盖主流宽基红利指数（沪深300红利、中证红利、红利低波、央企红利等），缺失的多为**同质化替代品**（多个港股红利指数彼此高度重合）
2. 数据源分散且反爬严格，维护成本高，收益边际
3. 若确实需要某几个特定指数，单独接比一次做全量更经济

---

## 四、推荐执行顺序

1. **先做方案 1**（PE 序列本地累积）—— 根治限流+并发+缓存冻结三类问题，性价比最高
2. 回填历史数据时**分批低并发**，避开中证封禁窗口
3. 上线后加 `pe_stale` 标记，前端提示数据新鲜度
4. 方案 2 暂缓，等实际业务需要再评估
