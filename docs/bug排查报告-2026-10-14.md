## P2（建议尽快修）

### P2-1 贵金属端点：上游 close 缺失时整端点 500

- 位置：`backend/services/market_service.py:2583-2586`（白银历史）、`:2596`（金银比黄金侧）
- 代码：
  ```python
  silver_hist = [
      {"date": r.get("date"), "price": round(_safe_float(r.get("close"), None) / 1000, 2)}
      for r in silver_rows
  ]
  ...
  ratio = _safe_float(r.get("close"), None) / (ag_raw / 1000)
  ```
- 问题：`_safe_float(..., None)` 返回 None 时 `/ 1000` 抛 TypeError → `/api/v1/market/precious-metals` 整端点 500。
- 不对称细节：同函数内当前价路径（2576-2577 `if s_price_raw else None`）和金银比的白银侧（2595 `if ag_raw and ag_raw > 0`）都有判空，唯独这两处没有。
- 触发条件：上游返回任一行 close 缺失/脏数据即触发，与当日行情无关。
- 线上现状：实测 200，数据完好（潜伏）。
- 修复建议：列表推导加 `if (v := _safe_float(r.get("close"), None)) is not None` 过滤；2596 黄金侧 close 判空后 `continue`。

### P2-2 成交额绝对变化反算公式错误（高估）

- 位置：`backend/services/market_service.py:1134-1137`
- 代码：
  ```python
  vol_change = market_stats.get("turnoverChangeAbs")
  if vol_change is None:
      pct = market_stats.get("turnoverChangePct")
      if pct is not None and total_e:
          vol_change = round(total_e * pct / 100, 2)
  ```
- 问题：`pct` 是**相对昨日成交额**的变化率（定义见同文件 841-843 行：`(total - yest) / yest * 100`），用当前成交额反推绝对变化的正确公式是 `total_e * pct / (100 + pct)`（同文件 `_calc_change` 347 行即此式）。现公式高估 `(100+pct)/100` 倍，例如 pct=+20% 时高估 20%。
- 触发条件：上游未提供 `turnoverChangeAbs`、仅提供 `turnoverChangePct` 时。
- 线上现状：实测今日 `volumeChange=0.0`（pct=0，公式恰好无差别），属潜伏缺陷。
- 修复建议：改为 `round(total_e * pct / (100 + pct), 2)`。

## 备案（当前数据形态下不触发，暂不改）

- `IndexAnalysis.vue` 布林映射依赖 `stepFull`/`step` stride 巧合：序列 ~240-260 个月时全点覆盖；若历史超 400 个月会出现带状偶发空洞。
- `IndexAnalysis.vue` `windowedHist`/`shiftMonths` 用 `toISOString()`（UTC）截取窗口，UTC+8 凌晨时段截止日可能差 1 天（月频序列边界，影响可忽略）。
- `valuation_service.py` `yield_10y` 单值无新鲜度护栏（spread 有 45 天护栏）。
- `fund_fee_service.py` `missing_codes` 的 deadline 用 CST naive，DuckDB 存 UTC（8h 偏差，30 天 TTL 下无实质影响）。
