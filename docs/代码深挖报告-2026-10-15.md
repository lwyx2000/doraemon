## 三、新发现问题（4 项，均低危）

### 问题 1：根目录 3 个死副本（P2，零引用）

`backend/fund_extra_metrics_service.py`、`backend/fund_fee_service.py`、`backend/fund_holdings_service.py`——mtime 全部为 2026-10-07 16:25:38（同批目录重构残留，与既往 `dividend_router.py` 死副本同类）。grep 全项目确认零 import。

- **风险**：后续任何按文件名检索/修改的操作都可能再次改错文件（本轮就踩了一次）；部署脚本若按 glob 传文件也会带上旧版
- **建议**：删除三个根目录副本（本地 + 53 宿主 + 容器镜像层）。**待批准**

### 问题 2：etf `_snapshot_daily` 无 dict 去重（P3）

当日 fund_rank(etf) 实测 3677 行、**零重复 code**，当前无实际影响。但：

- 原实现逐只 DELETE+INSERT 是「后写覆盖」；新实现同语句多行 VALUES 若出现重复 code，DuckDB **保留首个**（2026-10-14 实测）
- `_build_sw_industry_map`（P0-2）已做 `dict` 去重（last wins）保证语义一致，**etf 处不一致**
- **建议**：`_snapshot_daily` 收集 rows 前加 `dict` 去重（key=code，last wins），一行改动、与 P0-2 对齐。**待批准**

### 问题 3：1 行 `0000-00-00` 脏 trade_date（P3，既有问题）

基金 **028242** 上游「净值日期」返回占位符 `0000-00-00`：

- `_norm_date` 正则 `(\d{4})[年\-/.](\d{1,2})[月\-/.](\d{1,2})` 无年份/月份下限校验，`0000-00-00` 被当作合法日期
- `_safe_float(None)` 返回 0.0（既有行为），份额/规模/净值全 None → 落库 `('028242','0000-00-00',0.0,0.0,0.0)` 脏行
- **既有问题，非本轮引入**（正则与 _safe_float 均未改）
- **建议**：`_norm_date` 加 `int(year) >= 2000 and 1 <= month <= 12 and 1 <= day <= 31` 校验，非法返回 None 自然跳过。**待批准**

### 问题 4：DELETE+INSERT 组合的半毁窗口（P3，既有语义未恶化）

`Database` 包装器无显式事务，DuckDB 连接为 autocommit——`_ensure_fund_nav`（DELETE by code + 批量 INSERT）与 `_persist`（DELETE per quarter + 批量 INSERT）若批量写中途失败，会出现「旧数据已删、新数据写一半」。

- **本轮未恶化**：原 executemany 同为逐行提交（失败窗口逐行 vs 每 200 行一批，批量化反而更小）
- **多数点反而更安全**：etf / pe 两处改用无 DELETE 的 ON CONFLICT DO UPDATE，失败不动旧数据，且均有异常退回逐只写路径
- 引入显式事务属架构级改动（影响所有写路径的提交语义），**需单独提案，本轮不动**

## 四、已排除的疑点（排查过，确认无风险）

| 疑点 | 排查结论 |
|---|---|
| numpy 类型漏入 bulk_insert（`isinstance(np.int64, int)` = False → 字符串字面量） | 数据流全链路显式 `float()/int()/str()` 转换（`_num`/`_safe_float`/`_row_to_record`）或 JSON 反序列化，无漏入通道 |
| 其他高危写模式（INSERT OR REPLACE / to_sql / register+SELECT） | `INSERT OR REPLACE` 仅 strategy_library 快照一处（低频小量）；无 to_sql/register |
| bulk_insert 分批失败语义 | 实测：第 2 批起失败时第 1 批已提交——与 executemany 逐行提交同为「部分成功」，未恶化 |
| fear_greed recompute 保留 executemany | `_SCORE_UPDATE_SQL` 是 UPDATE 形态无占位组，走不了 VALUES 批量；回填量几百行 = 秒级，重构不值当 |
| `Database.execute` 的 `if params:` 对空 list 走无参分支 | 无实际调用点传空 params list |
| 死副本是否被 import（删除安全性） | grep 全项目零引用（不含 `services.` 前缀的 import 形式） |
